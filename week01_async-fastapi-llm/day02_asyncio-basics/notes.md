# Day 02 笔记：asyncio 同步 vs 异步耗时对比

## 实验设置
- 脚本：`bench_sync_vs_async.py`（环境：conda `dl-course`，Python 3.11）
- 任务：向 LLM 发送 5 个独立问题（一句话解释递归、闭包、装饰器、生成器、协程）
- 同步：`OpenAI` 客户端，for 循环串行请求
- 异步：`AsyncOpenAI` + `asyncio.TaskGroup` 并发请求
- 计时：`time.perf_counter`，每轮先同步后异步，共 3 轮取平均
- 模型：`gemini-3.8-flash-high`（OpenAI 兼容接口，`responses.create`）

## 结果

| 方式 | 3 轮平均耗时 | 相对同步 |
|---|---|---|
| 同步（串行） | 20.47 s | 1.00x |
| 异步（并发） | 5.14 s | 约 3.98x 更快 |

## 结论
1. 5 个请求并发后耗时约为串行的 1/4，接近单个最慢请求的耗时。请求之间互不依赖，所以并发收益明显。
2. LLM 调用是 IO 密集型任务：等待服务端返回时，事件循环可以去发起其他请求，不会空等。
3. 加速比（约 3.98x）小于理论值 5x，原因可能是：单个请求耗时有波动、总耗时由最慢的请求决定、服务端可能有限流。
4. 并发数增大后要用 `Semaphore` 限流，避免触发 429（Day 03 内容）。

## 局限
- 只测了 3 轮，每轮同步在前、异步在后，可能受服务端缓存和网络波动影响，没有交换顺序重复测试。
- 单轮耗时没有单独记录，只保存了平均值，看不出波动范围。
- 使用的是推理型模型，响应较长、耗时较大，结果不一定适用于其他模型。
